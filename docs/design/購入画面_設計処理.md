# 購入画面_設計処理

## 画面遷移

```
メイン画面 ──【購入画面へ】──→ 購入画面 ──【購入】──→ 購入確認画面
    ↑  ←────────【戻る】──────────┘
```

---

## 要件

| 要件 |
|---|
| メイン画面で選択した商品の情報（商品名・ジャンル・値段・出品者・在庫数）を表示する |
| 購入する数量を入力できる |
| 購入ボタンを配置する |
| 戻るボタンを配置し、メイン画面へ遷移できる |
| 購入ボタン押下で購入確認画面へ遷移する |

## 検討すべき要件

| 検討すべき要件 | 優先度 | 結果 |
|---|---|---|
| ログインしていない／セッション切れの場合はログイン画面へ遷移し、ログイン成功後この画面に戻す | 高 | ⇒採用 |
| 自分で出品した商品は購入できないようにする | 高 | ⇒採用 |
| 在庫が0の商品は購入できないようにする | 高 | ⇒採用 |
| 数量は1以上かつ在庫数以下に制限する | 高 | ⇒採用 |
| URLの商品IDを直接書き換えられた場合の対策 | 中 | ⇒採用 |
| 商品画像を表示する | 低 | |
| 出品者のレビュー（評価値）を表示する | 低 | |
| 複数の商品をまとめて購入する（カート機能） | 低 | |

## 詳細設計書

| ユーザーの操作 | ステップ | 処理内容 | YES | NO |
|---|---|---|---|---|
| 画面を開く | 1. ログイン済みか確認する | セッションにログイン済みフラグがあるか確認する | ステップ2へ | 商品IDを戻り先としてURLパラメータに付け、ログイン画面へ遷移する（ログイン成功後はこの画面に戻る） |
| | 2. 商品の存在チェックを行う | 受け取った商品IDが Sales に存在するか判定する | ステップ3へ | エラーメッセージ「商品が見つかりません。」→ メイン画面へ |
| | 3. 在庫のチェックを行う | Sales.Stock が 1 以上か判定する | ステップ4へ | 購入ボタンを非表示にし「この商品は売り切れです。」と表示 |
| | 4. 出品者のチェックを行う | Sales.Userid とセッションのユーザーIDが一致するか判定する | 購入ボタンを非表示にし「自分の出品した商品は購入できません。」と表示 | ステップ5へ |
| | 5. 商品情報を表示する | Sales と Genre を結合して商品名・ジャンル名・値段・出品者・在庫数を取得し表示する。数量の初期値は 1 | | |
| 戻るボタンを押す | 1. 画面遷移を行う | メイン画面へ遷移する | | |
| 数量を入力し、購入ボタンを押す | 1. 数量のチェックを行う | 数量が整数で、1以上かつ在庫数以下か判定する | ステップ2へ | エラーメッセージ「数量は1〜{在庫数}の範囲で入力してください。」→ 購入画面を再表示 |
| | 2. 購入情報をセッションに書き込む | 商品IDと数量をセッションに保存する | ステップ3へ | |
| | 3. 画面遷移を行う | 購入確認画面へ遷移する | | |

## 使用テーブル

| テーブル | 操作 | 使用カラム |
|---|---|---|
| Sales | SELECT | ProductID, GenreCode, ProductName, Price, Userid, Stock |
| Genre | SELECT | GenreCode, GenreName |
| UserData | SELECT | Userid, UserName（出品者名の表示） |

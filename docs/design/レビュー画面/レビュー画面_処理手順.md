# レビュー画面_処理手順

凡例（資料の記号との対応）

| 資料の記号 | 図での表し方 |
|---|---|
| 開始・終了（●） | `(( ))` |
| ユーザーの操作 | `[/ /]` |
| 処理内容（角丸） | `( )` |
| 分岐（◇） | `{ }` |
| 画面 | `[[ ]]` |

---

```mermaid
flowchart TD
    S((開始)) --> A[/状況確認画面で<br>受け取り完了・レビューを見るを押す/]
    A --> B{ログイン済みか}
    B -- NO --> R(商品IDを戻り先として<br>URLパラメータに付ける)
    R --> LOGIN[[ログイン画面]]
    LOGIN -- ログイン成功 --> C
    B -- YES --> C{商品が存在し<br>購入済みか}
    C -- NO --> E1(「商品が見つかりません。」) --> ST1[[販売状況確認<br>発送状況確認画面]]
    C -- YES --> D{自分が購入者<br>または出品者か}
    D -- NO --> E2(「自分が出品・購入した商品の<br>レビューのみ表示できます。」) --> ST1
    D -- YES --> F{レビュー済みか<br>sucre が NULL でない}
    F -- YES --> V(★評価とレビュー本文を表示)
    F -- NO --> G{購入者か}
    G -- NO --> W(「まだレビューはありません」を表示)
    G -- YES --> H{発送済みか<br>ShippingFlag = 1}
    H -- NO --> E3(「まだ発送されていません。<br>発送後に受け取り完了・<br>レビューができます。」) --> ST1
    H -- YES --> FORM(受け取り完了・<br>レビュー記入フォームを表示)

    V --> P1[[レビュー画面<br>表示]]
    W --> P1
    P1 -- 戻る --> ST2[[販売状況確認<br>発送状況確認画面]]

    FORM --> P2[[レビュー画面<br>記入フォーム]]
    P2 --> U{ユーザーの操作}
    U -- 戻る --> ST2
    U -- 評価値・本文を入力して<br>受け取り完了 --> CHK(画面を開くときの<br>チェックをもう一度行う)
    CHK --> X{評価値が1〜5<br>かつ 本文が100文字以内か}
    X -- NO --> E5(エラーメッセージを表示<br>入力内容は残す) --> P2
    X -- YES --> UP(Sales の sucre・revwe を更新<br>条件：購入者が自分<br>かつ 発送済 かつ 未レビュー)
    UP --> Y{更新件数が1件か}
    Y -- NO --> E4(「この商品はすでに<br>レビュー済みです。」) --> ST1
    Y -- YES --> OK(「受け取りが完了しました。<br>レビューを投稿しました。」)
    OK --> ST3[[販売状況確認<br>発送状況確認画面]]

    ST1 --> END((終了))
    ST2 --> END
    ST3 --> END
```

## 補足：レビュー登録のSQL（例）

```sql
UPDATE Sales
SET sucre = @Score,
    revwe = @Review          -- 空なら NULL
WHERE ProductID    = @ProductID
  AND BuyerName    = @Buyer  -- 自分が購入した商品
  AND ShippingFlag = 1       -- 発送済み
  AND sucre IS NULL;         -- まだレビューしていない（二重投稿対策）
```

- 条件を WHERE に全部入れておくことで、画面を開いた後に状態が変わっても不正な更新はされない
- 更新件数が 0 件ならレビュー済み（または条件を満たしていない）としてエラーにする

# レビュー画面_設計処理

## 画面遷移

```
販売状況確認・発送状況確認画面 ──【受け取り完了 / レビューを見る】──→ レビュー画面
              ↑  ←──────────【戻る / 受け取り完了（投稿）】──────────┘
```

---

## 要件

- 課題資料（システム概要例3）より：「受け取り完了ボタンを押したらレビューを書けるように」
- 課題資料（システム概要例3）より：「自分の出品、購入した商品のレビューが見れるように」
- 課題資料（最終的な確認事項・追加機能）より：「レビューを見れるようにする」

| 要件 |
|---|
| 販売状況確認・発送状況確認画面からのみ遷移し、戻り先も同画面とする |
| 対象商品の情報（商品名・値段・出品者または購入者・購入日時）を表示する |
| 購入者は、発送済みの商品について評価値（1〜5）とレビュー本文（100文字まで）を入力できる |
| 受け取り完了ボタンを押すと評価値・レビューを登録し、販売状況確認・発送状況確認画面へ遷移する |
| レビューの登録をもって「受け取り完了」とする |
| 購入者・出品者とも、レビュー済みの商品はレビュー内容（★評価・本文）を表示する |
| 戻るボタンで販売状況確認・発送状況確認画面へ遷移する |

## 検討すべき要件

| 検討すべき要件 | 優先度 | 結果 |
|---|---|---|
| ログインしていない／セッション切れの場合はログイン画面へ遷移し、ログイン成功後この画面に戻す | 高 | ⇒採用 |
| 自分が出品・購入した商品以外は表示できないようにする | 高 | ⇒採用 |
| レビューを書けるのは購入者だけにする（出品者は見るだけ） | 高 | ⇒採用 |
| 未発送の商品は受け取り完了できないようにする | 高 | ⇒採用 |
| レビューは1商品1回まで（レビュー済みなら表示のみ） | 高 | ⇒採用 |
| SQLへの不正なアクセスへの対策（SQLインジェクション） | 高 | ⇒採用 |
| 受け取り完了ボタンの二重押し対策 | 中 | ⇒採用 |
| レビュー本文の文字数を入力中に表示する | 低 | ⇒採用 |
| レビューの編集・削除 | 低 | 不採用 |

## 画面の表示パターン

| 条件 | 表示内容 |
|---|---|
| 購入者 かつ 発送済み かつ 未レビュー | 受け取り完了・レビュー記入フォーム |
| レビュー済み（購入者・出品者とも） | ★評価とレビュー本文 |
| 出品者 かつ 未レビュー | 状態（未発送／発送済み・受け取り待ち）と「まだレビューはありません」 |
| 購入者 かつ 未発送 | 表示しない（エラーメッセージを出して状況確認画面へ） |

## 詳細設計書

| ユーザーの操作 | ステップ | 処理内容 | YES | NO |
|---|---|---|---|---|
| 画面を開く | 1. ログイン済みか確認する | セッションにログイン済みフラグがあるか確認する | ステップ2へ | 商品IDを戻り先としてURLパラメータに付け、ログイン画面へ遷移する（ログイン成功後はこの画面に戻る） |
| | 2. 商品の存在チェックを行う | 受け取った商品IDが Sales に存在し、購入済み（BuyerName が NULL でない）か判定する | ステップ3へ | エラーメッセージ「商品が見つかりません。」→ 状況確認画面へ |
| | 3. 購入者・出品者のチェックを行う | Sales.BuyerName が自分、または Sales.Userid が自分か判定する | ステップ4へ | エラーメッセージ「自分が出品・購入した商品のレビューのみ表示できます。」→ 状況確認画面へ |
| | 4. レビュー済みか判定する | Sales.sucre が NULL でないか判定する | レビュー内容を表示する | ステップ5へ |
| | 5. 購入者か判定する | ステップ3で購入者だったか | ステップ6へ | 「まだレビューはありません」を表示する（出品者） |
| | 6. 発送状態のチェックを行う | Sales.ShippingFlag が 1（発送済）か判定する | 受け取り完了・レビュー記入フォームを表示する | エラーメッセージ「まだ発送されていません。発送後に受け取り完了・レビューができます。」→ 状況確認画面へ |
| 戻るボタンを押す | 1. 画面遷移を行う | 販売状況確認・発送状況確認画面へ遷移する | | |
| 評価値・レビューを入力し、受け取り完了ボタンを押す | 1. 画面を開くときのステップ1〜6を再度行う | 開いた後に状態が変わっていないか確認する | ステップ2へ（フォーム表示の条件を満たす） | エラーメッセージ「この商品はすでにレビュー済みです。」等 → 状況確認画面へ |
| | 2. 入力チェックを行う | 評価値が1〜5の整数か、レビュー本文が100文字以内か判定する | ステップ3へ | エラーメッセージを表示し、入力内容を残したままレビュー画面を再表示 |
| | 3. SQLインジェクションのチェックを行う | プレースホルダ（パラメータ化クエリ）を使用する | ステップ4へ | |
| | 4. レビューを登録する | Sales.sucre・revwe を更新する（条件：購入者が自分 かつ 発送済 かつ 未レビュー） | ステップ5へ（更新1件） | エラーメッセージ「この商品はすでにレビュー済みです。」→ 状況確認画面へ（更新0件） |
| | 5. 画面遷移を行う | 「受け取りが完了しました。レビューを投稿しました。」を表示し、販売状況確認・発送状況確認画面へ遷移する | | |

### 入力項目

| 項目 | 種類 | 必須 | チェック |
|---|---|---|---|
| 評価値 | ラジオ（★1〜5） | ○ | 1〜5の整数 |
| レビュー本文 | テキストエリア | | 100文字以内（空なら NULL で登録） |

## 使用テーブル

| テーブル | 操作 | 使用カラム |
|---|---|---|
| Sales | SELECT / UPDATE | ProductID, ProductName, Price, Userid, BuyerName, ShippingFlag, SoldDate, sucre, revwe |
| UserData | SELECT | Userid, UserName（出品者名・購入者名の表示） |

## 備考

- DBに「受け取り完了」を表す列がないため、**レビュー（評価値）が登録されている＝受け取り完了** として扱う
- BuyerName には購入者のユーザーIDを文字列で入れているため、購入者名は `UserData.Userid` を文字列に変換して結合する
- 販売状況確認・発送状況確認画面からは `review.php?productId=商品ID` で遷移する
  - 購入者：発送済み・未レビューなら「受け取り完了」ボタン、レビュー済みなら「レビューを見る」
  - 出品者：売れた商品に「レビューを見る」

# 購入確認画面_処理手順

凡例（資料の記号との対応）

| 資料の記号 | 図での表し方 |
|---|---|
| 開始・終了（●） | `(( ))` |
| ユーザーの操作 | `[/ /]` |
| 処理内容（角丸） | `( )` |
| 分岐（◇） | `{ }` |
| 画面 | `[[ ]]` |

---

```mermaid
flowchart TD
    S((開始)) --> A[/購入確認画面を開く/]
    A --> B{ログイン済みか}
    B -- NO --> X1(「セッションの有効期限が切れました。<br>再度ログインしてください。」)
    X1 --> LOGIN1[[ログイン画面]]
    LOGIN1 -- ログイン成功 --> MAIN0[[メイン画面]]
    B -- YES --> B2{セッションに<br>商品IDがあるか}
    B2 -- NO --> MAIN0
    B2 -- YES --> C(商品情報・合計金額と<br>配送先情報を取得して表示)
    C --> P[[購入確認画面]]
    P --> U{ユーザーの操作}
    U -- キャンセル --> BACK[[購入画面]]
    U -- 確定 --> D{セッションは有効か<br>ログイン済み かつ 商品IDあり}

    D -- NO --> Y1(購入処理を中止<br>DB更新はしない)
    Y1 --> Y2(「セッションの有効期限が切れました。<br>再度ログインしてください。」)
    Y2 --> Y3(hidden の商品IDを<br>戻り先としてURLパラメータに付ける)
    Y3 --> LOGIN2[[ログイン画面]]
    LOGIN2 -- ログイン成功 --> Y4{戻り先があるか}
    Y4 -- YES --> BACK2[[購入画面<br>販売状況・出品者チェックからやり直し]]
    Y4 -- NO --> MAIN0

    D -- YES --> T(トランザクション開始)
    T --> F(Sales の購入者名・購入日時・発送フラグを更新<br>条件：未購入かつ自分の出品でない)
    F --> G{購入状態を更新できたか}
    G -- NO --> RB1(ロールバック<br>「この商品は購入できません。」) --> BACK
    G -- YES --> K(コミット)
    K --> H(セッションの商品IDを削除)
    H --> MAIN2[[メイン画面<br>「購入が完了しました。」]]

    MAIN0 --> END((終了))
    BACK --> END
    BACK2 --> END
    MAIN1 --> END
    MAIN2 --> END
```

## 補足：セッション無効時の考え方

- 確定ボタンを押した時点でセッションが切れていたら、**購入は一切確定させない**
- セッションに保存した商品IDは消えているので、確認画面のフォームに hidden で商品IDを持たせておき、それを戻り先に使う
- ログイン後は確認画面ではなく **購入画面からやり直す**（切れている間に販売状況や値段が変わっている可能性があるため）

## 補足：購入確定時のSQL（例）

```sql
BEGIN TRANSACTION;

-- 未購入の商品を購入済みにする（自分の出品は不可）
UPDATE Sales
SET BuyerName = @BuyerName,
    SoldDate = GETDATE(),
    ShippingFlag = 0
WHERE ProductID = @ProductID
  AND BuyerName IS NULL
  AND SoldDate IS NULL
  AND Userid <> @LoginUserId;

-- 更新件数が 0 件なら ROLLBACK して購入失敗

COMMIT;
```

- SQL定義には `Stock` と `Purchase` テーブルがないため、1商品行を1回だけ購入できる状態更新として扱う
- 購入条件を UPDATE の WHERE 句で判定し、同時購入でも購入済み商品が再度確定されないようにする
- 値は必ずパラメータ（`@〜`）で渡し、文字列連結でSQLを組み立てない（SQLインジェクション対策）

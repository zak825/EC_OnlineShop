# 購入確認画面_設計処理

## 画面遷移

```
購入画面 ──【購入】──→ 購入確認画面 ──【確定】──→ メイン画面
   ↑  ←──【キャンセル】──┘
```

---

## 要件

| 要件 |
|---|
| 購入する商品の情報・合計金額と、配送先（ログインユーザーの名前・郵便番号・住所・電話番号）を表示する |
| 確定ボタン・キャンセルボタンを配置する |
| 確定ボタン押下で購入を確定し、Sales の購入者名・購入日時・発送フラグを更新してメイン画面へ遷移する |
| キャンセルボタン押下で購入画面へ戻る |

## 検討すべき要件

| 検討すべき要件 | 優先度 | 結果 |
|---|---|---|
| ログインしていない／セッション切れの場合はメッセージを出してログイン画面へ遷移し、ログイン成功後は購入画面からやり直させる | 高 | ⇒採用 |
| SQLへの不正なアクセスへの対策（SQLインジェクション） | 高 | ⇒採用 |
| 確定直前に他のユーザーが購入した場合の対策（同時購入） | 高 | ⇒採用 |
| 購入済み状態への更新をトランザクションで行う | 高 | ⇒採用 |
| 確定ボタンの二重押し対策 | 中 | ⇒採用 |
| 購入完了メッセージを表示する | 中 | |
| 出品者に購入されたことを通知する | 低 | |

## 詳細設計書

| ユーザーの操作 | ステップ | 処理内容 | YES | NO |
|---|---|---|---|---|
| 画面を開く | 1. ログイン済みか確認する | セッションにログイン済みフラグがあるか確認する | ステップ2へ | 「セッションの有効期限が切れました。再度ログインしてください。」を表示し、ログイン画面へ遷移する（ログイン成功後はメイン画面へ） |
| | 2. 購入情報の有無を確認する | セッションに商品IDがあるか確認する | ステップ3へ | メイン画面へ遷移する |
| | 3. 購入情報を表示する | セッションの商品IDで Sales を、ユーザーIDで UserData を取得し、合計金額と配送先を表示する | | |
| キャンセルボタンを押す | 1. 画面遷移を行う | 購入画面へ遷移する（商品IDを渡す） | | |
| 確定ボタンを押す | 1. セッションが有効か確認する | ログイン済みフラグと、商品IDがセッションに残っているか確認する | ステップ2へ | 下記「セッション無効時」の処理へ |
| | 2. SQLインジェクションのチェックを行う | プレースホルダ（パラメータ化クエリ）を使用する | ステップ3へ | |
| | 3. トランザクションを開始する | 以降のDB更新をまとめて扱う | ステップ4へ | |
| | 4. 購入状態を更新する | Sales の BuyerName・SoldDate・ShippingFlag を更新する（条件：未購入かつ自分の出品でない） | ステップ5へ（更新成功） | ロールバックし、エラーメッセージ「この商品は購入できません。」→ 購入画面へ |
| | 5. コミットする | トランザクションを確定する | ステップ6へ | |
| | 6. セッションの購入情報を削除する | セッションから商品IDを削除する | | |
| | 7. 画面遷移を行う | 「購入が完了しました。」を表示しメイン画面へ遷移する | | |

### セッション無効時

| ステップ | 処理内容 |
|---|---|
| 1. 購入処理を中止する | DB更新は一切行わない（購入は確定させない） |
| 2. メッセージを表示する | 「セッションの有効期限が切れました。再度ログインしてください。」 |
| 3. 戻り先を設定する | フォームの hidden 項目で送られた商品IDを戻り先としてURLパラメータに付ける |
| 4. 画面遷移を行う | ログイン画面へ遷移する |
| 5. ログイン成功後 | 戻り先の購入画面へ遷移し、販売状況・出品者チェックからやり直す。戻り先がなければメイン画面へ |

- セッション切れ中に販売状況や値段が変わっている可能性があるため、確認画面ではなく購入画面からやり直させる
- hidden の商品IDは書き換えられる可能性があるが、購入画面で存在・販売状況・出品者を再チェックするので問題ない

## 使用テーブル

| テーブル | 操作 | 使用カラム |
|---|---|---|
| Sales | SELECT / UPDATE | ProductID, ProductName, Price, Userid, BuyerName, SoldDate, ShippingFlag |
| UserData | SELECT | Userid, UserName, ZipCode, Address, TEL |

`sql/Sales.sql` に `Stock` および `Purchase` テーブルは定義されていないため、現行実装では Sales の1行を1商品として購入し、Sales の BuyerName・SoldDate・ShippingFlag を更新する。
